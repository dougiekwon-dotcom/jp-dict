# 요미 — 일본어 사전 + 단어장

일본어 책을 읽다가 모르는 한자·숙어를 찾는 PWA. 폰에 설치해서 쓴다.

<https://dougiekwon-dotcom.github.io/jp-dict/>

세 가지로 찾는다.

| 입력 | 예 |
|---|---|
| **한글 발음** | `경제` → 経済 · `도쿄` → 東京 · `코레` → これ · `korewa` |
| **일본어** | `経済` · `けいざい` · `食べ`(앞부분만) |
| **손글씨** | 화면에 이어 써서 한 번에. 한 글자든 문장이든, 한글로 써도 됨 |

## 한자 한 글자

한 글자를 쓰거나 치면 낱말이 아니라 **한자 카드**가 뜬다. 한국 한자음, 음독·훈독,
획수·JLPT·빈도, 그리고 **그 한자가 들어간 낱말들**. 책에서 모르는 한자를 만났을 때
알고 싶은 건 뜻만이 아니라 「어떻게 읽고 어떤 말에 쓰이는가」다. 전부 내장 사전에서
나오므로 AI를 기다리지 않는다.

손글씨로 한 글자를 썼을 때는 **1순위를 바로 카드로 보여주고**, 닮은 글자 후보를
그 아래 칩으로 깐다. 고르기 전에 아무것도 안 보여주는 방식(네이버 사전)은 맞은
경우에도 한 번 더 눌러야 한다. 후보는 같은 API 호출에서 함께 받으므로 왕복이
늘지 않는다. 칩에는 한국 한자음과 음독을 같이 적는다 — `未 미 ミ` / `末 말 マツ`
처럼 되어야 未·末을 눈으로 가릴 수 있다.

## 한자음 다리

한국인은 한국 한자음을 이미 알고 있으니 일본 음독을 규칙으로 건너갈 수 있다.
한·일 음독은 같은 중국 중고음에서 갈라져 나왔고 받침이 규칙적으로 대응한다.

| 한국어 받침 | 일본 음독 | 예 |
|---|---|---|
| 없음 | 모음 끝 | 사(思) シ · 도(道) ドウ |
| ㄱ | ク · キ | 국(國) コク · 석(石) セキ |
| ㄹ | ツ · チ | 일(日) ニチ · 발(發) ハツ |
| ㅂ | ウ | 십(十) ジュウ · 합(合) ゴウ |
| ㅁ · ㄴ | ン | 심(心) シン · 산(山) サン |
| ㅇ | ウ · イ | 동(東) トウ · 경(京) キョウ |

결과 카드에 `経 경 ケイ + 済 제 サイ` 와 `경제 → けいざい` 가 뜬다. 전부 오프라인
계산이라 AI 응답을 기다리지 않는다. 훈독으로 읽는 말(山 = やま)에는 붙이지 않는다.

## 구조

```
정적 PWA (GitHub Pages)
 ├ public/data/*.json   내장 사전 2MB — 검색은 오프라인·즉시·무료
 ├ IndexedDB            단어장 · 조회 로그 · AI 응답 영구 캐시
 └ api.anthropic.com    한국어 뜻·문장 해석·손글씨 인식 (브라우저에서 직접)
```

서버가 없다. 지하철에서도 사전 검색은 된다.

**AI는 타이핑 중에 부르지 않는다.** Enter를 치거나 후보를 고르는 등 확정한
순간에만 호출하고, 결과는 영구 캐시하므로 같은 낱말은 한 번만 결제된다.

작업마다 모델을 나눈다 — 뜻풀이는 읽는 법·영어 뜻을 사전이 대주므로 Haiku로
충분하고, 손글씨 판독만 한 단계 위(Sonnet 5)를 쓴다. 설정에서 프리셋으로 고른다.

## 쓰기

```bash
npm install
npm run dev
```

설정 화면에서 Anthropic API 키를 넣으면 한국어 뜻풀이·문장 해석·손글씨가 켜진다.
키 없이도 사전 검색과 한자음 다리는 된다.

> 키는 이 기기 브라우저(localStorage)에만 저장되고 브라우저에서 직접 호출한다.
> 이 앱 전용 키를 새로 발급하고 콘솔에서 사용 한도를 걸어 둘 것.

```bash
npm test       # 규칙 회귀 테스트 (한자음·음독 조합·한글 변환·순위)
npm run prep   # 사전 원본 → public/data 재생성 (tools/prep.mjs 상단 주석 참조)
npm run build
npm run deploy # 테스트 → 빌드 → gh-pages 브랜치로 배포
```

## 기기 연동

태블릿과 폰의 단어장·조회 기록·복습 상태를 합친다. 서버가 없으므로 **GitHub
비공개 Gist를 저장소로** 쓴다.

동기화는 늘 세 걸음이다: 내려받아 → 로컬과 합치고 → 합친 것을 되돌려 올린다.
병합 규칙은 백업 「가져오기」와 같다 — 조회 횟수는 큰 쪽, 별표는 하나라도 있으면
유지, 로그는 시각으로 중복 제거. 그래서 어느 쪽이 먼저 올라가든 결국 같아진다.

1. GitHub → Settings → Developer settings → Personal access tokens →
   **Tokens (classic)** → Generate new token → 권한은 **gist 하나만** 체크
2. 앱 **설정 → 기기 연동** 에 토큰 저장 → **저장소 만들기**
3. 나온 **연동 코드**(Gist ID)를 다른 기기의 같은 화면에 입력

이후로는 앱을 켤 때와 덮을 때 자동으로 합쳐진다.

**API 키는 동기화하지 않는다.** 기록과 자격증명을 같은 곳에 두지 않는다 —
기기마다 따로 넣어야 한다.

두 기기가 동시에 올리면 나중 것이 앞의 것을 덮을 수 있다. 밀린 쪽 기기에 원본이
그대로 남아 있어 다음 동기화 때 다시 올라가므로 데이터가 사라지지는 않는다.

## 배포와 버전

GitHub Pages를 `gh-pages` 브랜치 서빙 모드로 쓴다. 코드를 고친 뒤
`npm run deploy` 한 번이면 테스트·빌드·푸시까지 끝난다.

빌드할 때 커밋 해시와 날짜를 앱에 새겨 넣는다(`vite.config.js` 의 `define`).
**설정 → 버전** 에서 지금 그 기기에 떠 있는 버전을 확인할 수 있다.

```
dd24828 · 2026. 8. 9. 오후 12:21
```

해시 뒤의 `+` 는 커밋하지 않은 변경이 섞인 빌드라는 뜻이다.

PWA는 새 버전을 받아 두었다가 다음 실행에 적용하므로 「고쳤는데 폰에서는 왜
그대로지」가 생긴다. 같은 화면의 **업데이트 확인** 버튼이 지금 확인하고 바로
적용한다. 자동으로 새로고침하지는 않는다 — 낱말을 찾는 도중에 화면이 날아가는
쪽이 더 성가시다.

Actions 자동 배포로 넘기려면 OAuth 토큰에 `workflow` 스코프가 필요하다
(`gh auth refresh -h github.com -s workflow`). 스코프가 생기면 `.gitignore`
에서 `.github/` 를 빼고 `.github/workflows/deploy.yml` 을 커밋하면 된다.

### 알려진 한계

jmdict-simplified가 JMdict의 빈도 밴드를 `common` 불리언으로 접어버려 **단어 단위
빈도 데이터가 없다.** 그래서 같은 소리의 한자어 몇 쌍은 첫 순위를 못 맞힌다
(전화 → 電化·電話, 영화 → 英和·映画, 연습 → 演習·練習). 후보 목록에는 항상
들어 있고, 한 번 고르면 조회 로그가 그 뒤로 영구히 위로 올려준다.
